# SBIOT-H750 firmware: implementation roadmap

**Spec:** `stm32/docs/specs/2026-10-14-stm32-firmware-design.md` (approved by Codex in round 7, commit `8a52dbd`).
**Review history:** `stm32/docs/review/`. The round-7 gates are at the end of `codex-spec-2026-10-14-followup.md`.

The spec covers about ten subsystems that can be built and tested separately. They are split into **11 sub-plans**.

- **Each sub-plan delivers software that runs and is tested on its own**, and is reviewed and approved when it is done.
- **A sub-plan may start once every plan in its "Depends on" column is approved.** Plans whose dependencies are all approved may run in parallel. For example, 03 needs only 01, so it can run alongside 02.
- **Approvals and questions go to Codex**, in session `01a13a5c-61c9-7513-939a-1db3010a8954` (see `stm32/docs/review/`).
- **Only Plan 01 is written in full here.** Each later plan is written in full when its turn comes, from the then-current code, so that its steps contain real code rather than guesses.

**Order rationale:**
- Plan 01 unblocks everything and needs no hardware.
- Plan 02 retires the riskiest hardware assumption (XIP from QSPI bank 2) early.
- Plan 03 is host-only and can run in parallel with Plan 02. Plan 04 starts on the host but needs the board from Plan 02 for its last tasks.
- The `audit_keys.py` gate sits in Plan 11, because keys stay unread until MQTT (09) and LTE (10) exist.
- From Plan 05 on, each plan adds one subsystem on top of a booting board.
