# Plan 04a: OTA image format and the bootloader's install logic, host first

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The OTA logic of spec §11.2 and the app side of §11.3 exist as plain C over a NOR flash interface. They are proven on the host against simulated flash that loses power at every erase and program.

**Architecture:**
- **`components/ota`**, shared by the bootloader and the app:
  - `sha256`;
  - `ota_image`: header format and `img_check`;
  - `ota_app`: the staging writer.
- **`boot/install.c`:** one decision per boot.
  - Reload held: restore the factory image.
  - Factory slot unseeded: seed it from QSPI.
  - A new image in staging: install it.
  - Then run QSPI, or halt.
- **`tools/mkimage.py`:** writes the image header after the build.
- **`test/host/nor_sim`:** a NOR flash with partial writes and erases on a power cut, deadlines, failing regions and read errors.
- **`test_install`:** the §12.1 bootloader cases, plus three matrices. They cut power at every operation of an install (including the upload), a restore and a seeding.
- **`mutants_ota.py`:** shows that the tests catch 17 deliberate faults.
- **Board side:** nothing here runs on the board. Plan 04b wires the logic into the bootloader, with the SPI4 driver, QSPI programming, Reload sampling and the halt loop.

**Tech Stack:** C11, gcc with ASan/UBSan, GNU make, Python 3 (hashlib, zlib).

**Spec:** `stm32/docs/specs/2026-10-14-stm32-firmware-design.md` §5.1, §5.2, §11.1, §11.2, §11.3, §12.1 (bootloader row). **Roadmap:** row 04, split into 04a (host) and 04b (board).

## Design (spec §11.2)

- **Images:** `Q` in QSPI, `S` in staging (SPI4 0x110000), `F` in the factory slot (SPI4 0x280000, the former backup slot). "Valid" means passing `img_check`. A read error counts as not valid.
- **`copy`**, used by all three paths. The source is never written.
  1. Erase the destination's first sector first.
  2. Then, for every other sector: erase it and program its pages.
  3. Then program the first sector, leaving the 4-byte magic `SBIO` blank.
  4. Read the whole destination back against the source.
  5. Program the magic, as the very last program, on its own.
  6. `img_check` the destination, whose header must equal the source's byte for byte.
- **Each boot, in order:**
  1. **Reload held 5 s.** Check `F`; if it is bad, halt and write nothing. Erase staging's first sector, so its image is never installed again. Then `copy` F → QSPI. Any failure halts.
  2. **Seeding.** If `Q` is valid and the factory slot has no magic, `copy` Q → factory. A failure is only reported. Because the magic is written last, a cut seeding is retried. An unreadable magic counts as present.
  3. **New image.** If `S` is valid, and `Q` is not valid or its header differs from `S`'s, `copy` S → QSPI. A failure halts. A cut install is redone from the start at the next boot, because `S` still differs from `Q`.
  4. **Run or halt.** Jump if `Q` is valid, else halt.
- **Halt:** blink fast, keep kicking, wait for Reload (Plan 04b). There is no automatic retry, no automatic factory restore, no trial and no rollback.
- **App side:** `ota_stage_begin(st, spi, total)`, `ota_stage_write`, `ota_stage_finish`.
  - `begin` erases staging's first sector at once, so the image staged before is gone.
  - Every 4 KB sector is erased just before it is written, and the magic is left blank.
  - `finish` programs the magic only after the SHA-256 matches.
  - The header is checked as soon as its core arrives.
  - The SHA-256 is computed on the fly.
  - At the end, staging is read back with `img_check`.
  - OTA_OK means reboot. There is no record and no confirm.

## Rulings (decisions taken while simplifying, for review)

1. **No boot record at all.** "New firmware" is a valid staging image that QSPI does not already hold. A cut install is detected by `Q` failing its check or its header differing. Cost if wrong: an image identical to the running one is never re-installed, which is the intent.
2. **The factory image is seeded by the bootloader** from the first valid QSPI image, when the factory slot has no magic. Production keeps flashing only QSPI, with the team's loader; there is no SPI4 loader. Cost if wrong: a field device whose factory magic got erased is re-seeded with its current firmware.
3. **A factory restore keeps the configuration.** `cfg`, `edge` and `cert` stay; the app's Reload 3–15 s config reset is separate. The app counts a press only after a release, so the restore gesture does not also reset the config. Cost if wrong: an old factory firmware reading a newer configuration; Plan 05's store must load unknown or newer keys tolerantly.
4. **The restore path halts if staging's first sector cannot be erased.** It does so before QSPI is touched. Otherwise the next boot would install staging over the factory image. Cost if wrong: a board with a failing SPI4 halts on Reload while QSPI still holds a runnable image.
5. **The magic is a separate final program, after a full read-back** (Codex r4). Without it, either of these leaves a factory slot with a magic but no valid image, which is never re-seeded:
   - a cut inside the header page during seeding;
   - a page that was programmed wrong without reporting an error.

   The `seed` matrix, `test_seed` and mutants 1, 2 and 15 pin this. The staging writer follows the same rule, so an upload cut short over an older image with the same tail is never installed.
6. **A cut inside the staging erase of a restore may leave staging intact** (Codex r4). The next normal boot then installs it, and the user holds Reload again. The `restore` matrix stages v3 ≠ QSPI v2, and allows this only for a cut at that operation.

## Global Constraints

- **Image header** (offsets in bytes, little endian):
  - 0: magic `SBIO`;
  - 4: hardware id `SBIOT-H750`, NUL-padded to 16 bytes;
  - 20: version, 3 × u16, then u16 0;
  - 28: body size, u32;
  - 32: SHA-256 of the body;
  - 64: CRC-32 of bytes 0–63;
  - 68–1023: 0xFF.
- **Image size and vectors:**
  - the body starts at 0x400 with the vector table, and its size is 8 bytes to 1 472 KB − 1 KB;
  - MSP inside (0x20000000, 0x20020000] or (0x24000000, 0x24080000], 8-byte aligned;
  - the reset vector has the Thumb bit and lies in [0x90000400, 0x90000400 + size).
- **Flash map:**
  - QSPI: slot at 0.
  - SPI4: staging 0x110000, factory 0x280000; 0x100000 is reserved.
  - The slot is 0x170000 bytes. An erase is 4 KB, a program one 256-byte page.
- **Code style:**
  - our C is `-std=c11` with the existing host flags (`-Wall -Wextra -Wno-unused-parameter -Werror -O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all`), 4-space indent, `//` comments;
  - `components/ota` and `boot/install.c` use no HAL and no OS.

## Review Focus

1. **A power cut inside any erase or program**, including the app's upload, and repeated cuts.
   - An install must end on v1 (cut before the upload finished) or v2.
   - A restore must never install staging again, and Reload must then give the factory image.
   - A seeding must end seeded, with the app running.

   Pinned by the three matrices and `test_spot_cuts`.
2. **Jumping into an image that fails its check.** This must never happen. The harness re-checks QSPI on every jump.
3. **Silent faults:** a program that reports success and does nothing, or a read error in the middle of a copy. Pinned by `test_copy_failures` and `test_read_errors`.
4. **Writes where none are allowed:**
   - a blank board, or bad QSPI with nothing to install: halt, no writes;
   - Reload with a bad factory image: halt, no writes;
   - staging bad, or the same image as QSPI: no writes;
   - unreadable factory slot: no seeding.

   Every one of these asserts zero erases and programs.
5. **Tests that pass without testing:** `damage()` asserts that the image became invalid, and `mutants_ota.py` (17 mutants) runs.
