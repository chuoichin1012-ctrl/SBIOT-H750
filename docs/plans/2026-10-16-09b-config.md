# Plan 09b: the config pipeline (defaults in FlashDB, plain saves, the device runs what it is given, rules in the UI)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the user's direction of 2026-10-16:
- the web UI validates every config and sends it whole;
- the gateway only stores it: it checks authentication, the name, the size, the JSON syntax and the write;
- **the device runs with the config it is given** (the user, 2026-10-16, r3): a wrong config may leave it not working or not connected; handling that is the user's job (fix it, or Reload). The loader only keeps memory safe;
- FlashDB is created with the defaults, from the one table they live in, and a factory reset rebuilds it with `fdb_kv_set_default`.

**Architecture:**
- **`store`** gets a FlashDB default KV table built from `cfgmodel`'s defaults. Its save path becomes a syntax check and a write: no merge, no normalisation, no rules. `edgeDevices` is split into 8 KB records by byte, behind the same generation and manifest.
- **The loader** (`store_get`) takes each field of the stored config: a value of the right type and within the schema's bounds is used; any other, and a missing key, take that field's default (logged). No config is refused as a whole, nothing is switched off, there are no states. Edge's model loads as today (`cfg_edge_load`, passes 1–2).
- **The UI** carries every rule in one TypeScript module, `rules.ts`, and sends whole, minified configs.

**Tech stack:** C (FlashDB 2.2.0, cJSON, `jsonscan`), TypeScript (React UI, `node --test` on `tsc` output), Python bench.

**Spec:** [2026-10-14-stm32-firmware-design.md](../specs/2026-10-14-stm32-firmware-design.md):
- §9.1: FlashDB (defaults, factory reset, validation at boot);
- §9.3: limits of the small configs;
- §9.4: saving `edgeDevices`;
- §10.3: the STM32 web UI;
- §11.4: the Reload button.

**Decisions:** asked of Codex, `stm32/docs/review/codex-gpt-6-astra-config-pipeline-design-2026-10-16.md` (D1–D8).

**Roadmap:** a new row 09b, between 09 (MQTT) and 10 (LTE). 09c (RAM: the static arena and the 48 KB Edge buffer gone, small buffers, streaming syntax check) follows, then the node limit is decided from 09c's measurements.

## Global Constraints

- **Limits:**
  - a small config's body is at most **10 240 bytes**, and `edgeDevices` at most **49 152 bytes**, NUL not counted;
  - an over-long body gets 413, and the stored config is kept.
- **A save checks only:**
  - authentication;
  - the name: 404 for an unknown one;
  - the size;
  - the JSON syntax, by `jsonscan` (RFC 8259, depth ≤ 32): 400 `The request body is not valid JSON.`;
  - the root type: an object for `network`, `port1`, `port2`, `mqtt`, `system`, `io`, `edge` and `edgeReport`; an array for `mqttPublish`, `mqttSubscribe`, `edgeDevices` and `edgeLinkage`. Otherwise 400 `The settings must be a JSON object.` or `… a JSON array.`;
  - the write: 500 on a flash error.

  There is no merge: the body replaces the whole config, and is stored byte for byte as sent.
- **GET returns what was stored, byte for byte.** The runtime uses what the loader made of it at boot.
- **Configs are read once, at boot.** Nothing is reconfigured live (spec §9.1).
- **Edge:** every record is written first, then the manifest; the manifest is the commit point (spec §9.4, kept as is).
- **No rescue mode,** no automatic switch to another admin config, no pending state, no rollback, no services switched off for a wrong config, no error states. When the web cannot be reached, the Reload button resets the configs.
- **The device need not handle every fault itself** (the user, 2026-10-16): keep it simple, and record a known limit rather than add machinery.
- **Factory reset ≠ firmware restore.** Restoring the firmware stays the bootloader's job (spec §11.2).
- **Keep it simple, run only the affected tests, TDD.** No FlashDB patching beyond the recorded patch. Codex reviews before the PR.

## Review Focus

1. **A config saved by the previous firmware** (normalised, every field filled; `edgeDevices` cut by byte into 8 KB records). It loads and runs as before; GET returns its bytes. Pinned in T3 by `test_store` cases that store such texts (made by `cfg_validate_text` and `cfg_edge_text`, as the previous save path did) and load them.
2. **A key the new firmware adds, missing from an old config.** Filled with its default; the rest is used as stored. Pinned in T3 by `test_cfgmodel`.
3. **A power cut during a factory reset** (three databases, not atomic). After the next boot, every config is either the default or the old saved one, never torn; the user presses Reload again if needed. Pinned in T1 (done).
4. **A field of the wrong type, out of the schema's bounds, or a string longer than its buffer.** That field takes its default and the service runs with the rest, so nothing reads past a buffer or indexes past an array. Pinned in T3 by `test_cfgmodel`, for every field kind.
5. **A list longer than its limit** (topics, events, devices, points). The first ones up to the limit are used. Pinned in T3 by `test_cfgmodel`.

## Rulings to approve

1. **One source of defaults.**
   - `store` builds a `struct fdb_default_kv_node` table once, before `fdb_kvdb_init`, from `cfgdef_t.defaults`: one entry per small config, plus `edgeDevices` = `[]` with no manifest.
   - The table and its strings are static for the whole run, because FlashDB keeps the pointer.
   - A new DB (the first mount, or after a format) is written with these values.
   - A key missing from an older DB (a config a newer firmware added) is read from the same table at boot, and is not written.
2. **Factory reset** (`store_factory_reset`, from Reload and `POST /api/factory-reset`):
   1. it blocks every later write until the restart: configs, certificates, `edgeDevices`, and the DO state of `keepOutputs`;
   2. it calls `fdb_kv_set_default` on `cfg`, `edge` and `cert`;
   3. it reads every default back. FlashDB 2.2.0 ignores `create_kv_blob`'s result in `fdb_kv_set_default` (`fdb_kvdb.c:1435`), so only the read-back proves the reset;
   4. it restarts the gateway.

   It reports `factory settings restored` or `factory reset incomplete`, and restarts either way. The three DBs are not atomic together: after a power cut, the user presses Reload again.

   **Only a mounted DB is reset.** A DB that did not mount (ruling 10), or a flash that the FAL has locked read-only after a read error (spec §9.1, kept as is), is left alone; the reset reports `incomplete` and restarts, and the next boot tries again.
3. **The save path** is a plain store (Global Constraints).
   - `store_set_text` no longer calls `cfg_validate_text` or `listen_check`, and no longer parses.
   - `store_edge_save` checks the syntax and the root type over the whole body. It cuts the body into 8 KB records by byte, even in the middle of a UTF-8 sequence, then writes the generation and the manifest as before.
   - `edgeReport`'s save-time template check goes. It moves to the UI, and to the boot's `TEMPLATE TOO LARGE` (spec §9.4, kept: **only the reports** go off, Edge runs; an `edgeReport` that fails the loader's check stops Edge, ruling 5).
4. **The loader keeps memory safe, nothing more** (the user, 2026-10-16, r3).
   - `cfg_load` (used by `store_get`) goes **field by field**: a value of the right JSON type and within the schema's bounds (numbers in range, strings within their length, enums known) is used; any other value, and a missing key, take that field's default, with one log line naming the config and the field. The config is never refused as a whole.
   - Lists keep their first entries up to their limit (16 topics, 10 events).
   - The cross rules (an empty user name or password, `idleRestart` under 60, two listeners on one port) are **not** checked: the device runs as configured, and a clash just fails to listen (logged by the service). `allowedClients` that does not parse takes its default (empty), because its parser feeds a fixed table.
   - Edge's model loads as it does today, `cfg_edge_load` passes 1–2 (structure, limits, names); a model it refuses leaves Edge off with its state, as today. Pass 3 (the save-time rules) is the UI's.
   - The cache holds the stored bytes (T2); GET serves them. `store_get` parses them and runs `cfg_load` each time it is called; services call it once, at boot.
5. **What T1 and T2 already did stays:** the default table, the reset (write block, read-back, restart), the plain save path, the FAL lock after a failed write (Codex, `codex-gpt-6-astra-plan09b-t2-flashdb-2026-10-16.md`). Rulings 5–7 and 10 of r2 (services off, safe mode, listen order, unmounted DB states) are **withdrawn** by the user's direction; a cfg DB that does not mount keeps today's behaviour (the defaults).
6. **The UI holds every rule.**
   - `stm32/web/src/lib/rules.ts` covers each field's type and range; the cross rules (listen ports, a non-empty user name and password, `idleRestart` of 0 or at least 60, `allowedClients`); the Edge model rules of `cfgmodel` passes 1–3 (spec §9.4 table); and the report template's worst-case size, by a port of `edge_tmpl_size` (`edgecore.c:407`), against **26 624 bytes**.
   - Pages call it before saving, show the errors, and send the whole config.
   - No code generation and no cross test: the C side no longer gives verdicts. `rules.test.ts` holds the cases.
7. **Certificates** keep their PEM and mbedTLS checks at upload (Codex D8). 09c moves their buffer to the heap.
8. **The UI sends minified JSON** (the user, 2026-10-16): every body is `JSON.stringify(value)` with no indentation. `rules.test.ts` checks the bodies the pages build.

## Architecture

### `components/store/` (T1, T2: done)

- `store.c`: the default table, the plain save path, the raw cache, `store_get` = parse + `cfg_load`, the factory reset.
- `fal_nor.c`: the lock after a failed program or erase.

### `components/cfgmodel/`

- `cfg_load`: field by field (ruling 4); the save-time `cfg_validate`/`cfg_validate_text` stay for the host tests' oracles only, or go if nothing uses them.

### `stm32/web/`

- `src/lib/rules.ts`, pure: `configErrors(name, value, all)`, `edgeModelErrors(devices, env)`, `templateSize(template, devices, report)` (bytes, as `edge_tmpl_size`), `body(value)` (minified JSON).
- The pages use it, and save whole objects.
- `tests/unit/rules.test.ts`, plus `tsconfig.test.json` (CommonJS output to `.test-build/`). Run with `npm run test:unit`, which is `tsc -p tsconfig.test.json && node --test .test-build/tests/unit`.
