# Plan 06b: Mongoose web, `/api/*`, UI and clock

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The gateway serves its web UI and the whole `/api/*` over Mongoose, has a WebSocket console and a clock (SNTP or `POST /api/time`, timezone, "clock not set"). On the bench, the `stm32/web` UI saves and reloads the settings of every page. This is configuration only: the services behind the settings come in Plans 07–10.

**Spec:** §5.3 (AXI: arena 64 KB, Edge buffer 48 KB, `web` stack), §6.1 (`web`, `console`, `restart`), §6.3, §6.4 (Mongoose rules), §9.1 (configs at boot), §9.3, §9.4 (Edge body), §10. **Roadmap:** row 06b.

  - `GET /api/config/*` returns what is saved; `/api/device` returns the running values.

## Architecture

- **Mongoose 7.23** (2026-08-12; GPLv2, the user knows), vendored and pinned in `third_party/mongoose`, with `app/mongoose_config.h`:
  - `MG_ARCH_ARMGCC`, `MG_ENABLE_FREERTOS`, `MG_ENABLE_LWIP`;
  - `MG_TLS_NONE`;
  - `MG_IO_SIZE` 1460, `MG_MAX_RECV_SIZE` 12 KB (a 10 240-byte body plus its headers);
  - `mg_random` from `board_rng`.

  It allocates through newlib, so from the one heap_5 heap (spec budget about 40 KB).
- **`components/webapi`**, rewritten on Mongoose. The JSON logic is kept from the ESP32 `api.c`.
  - **`web_core.c`, pure and host-tested:**
    - the login token: base64 of `user:password`, built once at boot, with a constant-time compare;
    - the `Authorization: Basic` header and the `?auth=` of the WebSocket, URL-decoded;
    - the config name from the URI;
    - the body policy:

      | Endpoint | Content-Length missing or chunked | Limit | Over the limit |
      |---|---|---|---|
      | OTA (streamed) | 411 | the slot | 413 |
      | certificate (streamed) | 411 | 12 KB | 413 |
      | `edgeDevices` (streamed) | 411 | 48 KB | 413 |
      | everything else | | 10 240 B | 413 |

    - the stall rule: two 15 s waits in a row without a byte means 408;
    - the PEM structural check (see ruling 1).
  - **`web.c`:** the `web` task (8 KB static stack in AXI, priority 5), one `mg_mgr` on `system.webPort` (read at boot), polled every 20 ms.
    - The UI is served gzip, without auth, with an ETag per file and 304; `/` gives `index.html`.
    - `/api/*` checks the Basic login and answers 401 **without** `WWW-Authenticate`.
    - At most 8 web connections: one more is closed at accept.
    - JSON work runs inside an **arena** scope (64 KB TLSF in AXI, spec §9.3; `json_alloc_install` routes cJSON there).
      - **A scope belongs to the task that opened it** (Codex r1). `arena_begin` records `arena_port_self()`: the task handle on the board, a fake in the host test.
      - `arena_current()` gives the arena only to that task, so cJSON calls from the UART7 console or `console` stay on the heap.
      - **A scope never spans two callbacks:** it opens and closes inside one Mongoose event. For the Edge POST, that is the one call that validates the complete body.
    - **Body limits are checked at `MG_EV_HTTP_HDRS`** (`web_core` policy), before Mongoose could close the connection on its own `MG_MAX_RECV_SIZE`. A chunked or over-long request gets its 411 or 413, then the connection drains.
  - **Streamed endpoints:** they are taken at `MG_EV_HTTP_HDRS`, the headers are dropped from `c->recv`, and `c->pfn` is set to NULL (Mongoose's `file-upload-single-post` idiom). Data then arrives as `MG_EV_READ`.
    - `/api/ota` → `ota_stage_begin/write/finish` into staging, then a restart after 1.5 s; the bootloader installs. One upload at a time: 409.
    - `/api/cert?scope=mqtt|port1|port2&kind=ca|cert|key` → `store_cert_set`.
    - `POST /api/config/edgeDevices` → the 48 KB Edge buffer in AXI → `store_edge_save`.

    `MG_EV_POLL` times the stall; on a stall the buffers are freed and the answer is 408.
  - **Streamed answers, bounded by the reader** (Codex r1): Mongoose appends whatever is sent to `c->send` on the heap, so a client that stops reading must not make it grow. Each streamed answer is a small state on the connection, pumped on `MG_EV_POLL` and `MG_EV_WRITE`. It adds its next piece only while `c->send.len` is under 4 KB (spec §9.4):
    - **the UI files** (`app.js` is 42 KB gzip), straight from QSPI;
    - **`GET /api/config/edgeDevices`:** `store_edge_pin` once, then `store_edge_record` by record. Every exit path unpins: done, error, `MG_EV_CLOSE`;
    - **`GET /api/log`:** the flash log (`[YYYY-MM-DD hh:mm:ss]` or `[boot N +hh:mm:ss]`), then the RAM ring. It resumes by counting the lines already sent, since the iterators take a callback.
  - **The other endpoints, as on the ESP32:**
    - `/api/device`: model `SBIOT-H750`, firmware `APP_VERSION`, hardware `STM32H750VBT6`, `portmax` 2, io 2/2/2/0, and the running hostname, `wsPort` and `wsDirection`;
    - `/api/status` (below);
    - `GET` and `POST /api/config/<name>` (`store_get_json`, `store_set_text`);
    - `/api/time`;
    - `/api/restart`;
    - `/api/factory-reset` (`store_factory_reset`, then a restart);
    - a 404 JSON for any other `/api/*`, sent after the auth check.
  - **`console.c`:** the `console` task (4 KB in DTCM, priority 5) with its own `mg_mgr` on `system.websocketPort`, started only when `websocketTarget` is not 0.
    - The login is checked **before** the upgrade; a wrong one gets 401.
    - At most 4 clients.
    - **LOG mode** (`websocketTarget` 3): a MessageBuffer (2 KB) written only by the `syslog` task, through its tap. `console` drains it after each `mg_mgr_poll` (20 ms) into text frames; a full buffer drops the line and counts it. Commands: `help`, `status`, `restart`.
    - **A client that stops reading** (Codex r1) gets no frame while its `c->send` is over 4 KB. The frame is dropped and counted, and the other clients go on.
    - **UART modes** (1, 2): accepted, but they say "the UART console starts with the serial driver" until Plan 07 (ruling 3).
- **`components/sysmgr`:**
  - **`clock.c`, pure and host-tested:**
    - civil date and time to Unix seconds and back, without `mktime` or TZ;
    - the strict parse of `"YYYY-MM-DD hh:mm:ss"`: real dates only, from 2024 to 2099;
    - local time = UTC + `timezone` hours (−12 to +12, as the config allows);
    - formatting.
  - **`sysmgr.c`:**
    - the wall clock is an offset over `now_us()`; "not set" until SNTP or `POST /api/time`;
    - lwIP's `sntp` app on `ntpServer` (by DNS) when `ntp` is 1, with `SNTP_SET_SYSTEM_TIME_US` setting the clock (Codex r1):
      - it runs in the lwIP core: it is set up under `LOCK_TCPIP_CORE`, and the server name stays in a static buffer for the whole run;
      - the 64-bit offset is read and written inside a critical section;
    - `store_port_wall_ms` comes from here, so log lines carry the date once the clock is set;
    - the restart task (3 KB, priority 10): it logs, waits, then calls `NVIC_SystemReset`;
    - the serial number from the UID; the uptime;
    - `sysmgr` starts last in `init` (spec §6.3) and logs the services' results.
  - Not set: `system.time` is `""` and the log uses `[boot N +hh:mm:ss]` (§10.4). No RTC, no LTE time.
- **`/api/status` on the STM32:**
  - `system`: uptime, os `"FreeRTOS + lwIP"`, mac, `imei` `""`, sn, `activeNet` ETH or NONE, time, `heapFree`, `heapMin`, `psramFree` 0, `wdiMaxGapMs`;
  - `eth`: the running addresses;
  - `cell`: state `disconnected`, empty fields (Plan 10);
  - `ports[2]`, `mqtt`, `edge`: state `"NOT STARTED"` until Plans 08 and 09, with `enabled` from the saved configs;
  - **`mem`:**
    - `heap` `{free, min}`;
    - `arenaPeak`;
    - the pools `{used, size}`: netconn, tcp_pcb, tcp_seg, pbuf_pool, the lwIP heap, the console MessageBuffer;
    - `stackMin` `{task, words}` over every task (`uxTaskGetSystemState`);
    - `uart` `{overrun, dropped}`: 0 until Plan 07.
- **UI:** `npm run build:firmware` (the embedded copy predates the latest `stm32/web`).
  - `tools/embed_web.py` also writes `www_blobs.S`: one `.incbin` per gzip file in `.rodata`, so in QSPI.
  - Assembling avoids `objcopy -I binary`, whose objects have no ARM attributes.
- **Init order** (spec §6.3): store, syslog, netmgr, then `webapi` (`web`, `console`), then `sysmgr` last.
  - The UART7 bench console stays: the bench scripts use it.

## Rulings to approve

1. **`/api/cert` without mbedTLS until Plan 08.** mbedTLS arrives with `tlsconn` (Plan 08). Until then the PEM is checked for its structure only:
   - one `BEGIN`/`END` pair matching the kind (`CERTIFICATE` for ca/cert; `PRIVATE KEY`, `RSA PRIVATE KEY` or `EC PRIVATE KEY` for key);
   - `ENCRYPTED PRIVATE KEY` refused;
   - base64 lines only.

   It is then stored. The answer is `{restartNeeded: true}` without `subject`, `validTo` or `pairMatches`; Plan 08 adds the full parse. Cost if wrong: a malformed certificate is accepted now and refused at the first TLS connection in Plan 08.
2. **`/api/io` answers 503** ("The IO module starts with a later firmware") until Plan 07. The IO page's live panel shows that error; its settings still save and reload.
3. **The UART modes of the WebSocket console** connect, then say they start with Plan 07. LOG mode is complete.
4. **Services in `/api/status` read "NOT STARTED"** until their plans. `mem.uart` counters are 0.
5. **An arena scope per request** in the `web` task. `console` and the UART7 console parse nothing big, so they stay on the heap.

## Bench findings

- **B1. Mongoose re-emits `MG_EV_HTTP_HDRS` on every read and poll** while a request's body is incomplete (`http_cb` reparses). The handler reset its stall timer each time, so a plain body that stopped never got its 408. The headers are now handled once per request (`hdrs_done`).
- **B2. An answer at the headers, then a close, reset the connection.** lwIP sends a reset when a socket closes with unread data, and the client lost the 413 or 411. The rejected body is now read and dropped before the close (`ST_DISCARD`): up to the announced length, at most 64 KB; for a chunked body, until 300 ms of quiet.
- **B3. Handwritten answers must end the response for Mongoose** (`c->is_resp = 0`): the pumped UI files and 304. Without that, the next request on a keep-alive connection was never parsed, and Chromium's page load hung. curl, with one request per connection, did not show it.
- **B4. 8 KB Edge records were corrupted on the bench board:** CRC errors, then `??` on GET.
  - **The cause:** the edge partition had been formatted at some time with 4 KB sectors, against the 16 KB the store mounts with.
    - FlashDB checks only the headers at 16 KB boundaries, which the old layout also has, and took the rest as erased.
    - A new record was then programmed over the old headers at every 4 KB boundary inside it: `"mer` read `02 44 40 30`, the KVDB magic `FDB0` ANDed into the text.
    - Small records never reach a 4 KB boundary.
  - **The proof:**
    - a raw 8 KB write and read through `flash_spi4` at an unaligned offset is clean;
    - a dump of every 4 KB block showed a header in each;
    - a factory reset formatted the partition with 16 KB sectors, after which the 100-point model (19 652 B of canonical text) saves and reads back.
  - Every committed version uses 16 KB, so the origin is unknown, probably an early bring-up build. A blank board is formatted right.
  - **Not patched** (the user's rule: no more FlashDB fixes); recorded as a known limitation. Cost if wrong: a board whose flash holds another layout corrupts its first large records, until a factory reset.
- **B5. The UI is embedded as C arrays** (the user's suggestion), not `.incbin`. `embed_web.py` writes the gzip bytes into `www_files.c` (428 KB of text), and the image is byte-identical.
- **B6. The user suggested shorter JSON keys for Edge.** This is deferred: the keys are the API contract with the UI, and 100 points take 19.6 KB of the 48 KB limit. Omitting fields that hold their default is the cheaper option if space gets tight.

## Codex round 1 (NOT APPROVED), and the fixes

1. **The arena was global:** a scope now belongs to its task, and spans one callback (T2b).
2. **Slow readers:**
   - every streamed answer is pumped only while `c->send` holds under 4 KB: UI files, Edge GET, log;
   - WebSocket frames are dropped for a client over 4 KB;
   - every exit path unpins;
   - bench case with two clients that never read.
3. Body limits checked at `MG_EV_HTTP_HDRS`, with a test above `MG_MAX_RECV_SIZE`. SNTP is set up under the core lock, with a static name and the offset read and written in a critical section.
