# Plan 09c: RAM (no static arena, small buffers, measured)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the user's item 6 of 2026-10-16:
- the static JSON arena goes, now that nothing depends on it;
- configs are received and read through small buffers;
- RAM is measured again before the node limit is raised.

**Architecture:**
- **The arena:** cJSON allocates on the heap, through the counting allocator (installed before `store_init` since 09b). The TLSF arena and its 64 KB go.
- **`edgeDevices` saves stream** into the store's 8 KB record buffer while a streaming syntax scanner runs alongside. The manifest is committed only when the whole body has arrived and is valid. The 48 KB body buffer goes.
- **The boot** reads the Edge model into a temporary heap buffer and frees it once the model is loaded.
- **Certificates** use a 12 KB heap buffer for the upload only; a key is wiped before it is freed.
- **The heap** gets 96 KB of the freed AXI.

**Tech stack:** C (FreeRTOS `heap_5`, FlashDB, cJSON, `jsonscan`), Mongoose, Python bench.

**Spec:** [2026-10-14-stm32-firmware-design.md](../specs/2026-10-14-stm32-firmware-design.md):
- §5.3: RAM;
- §9.3: the arena and the Edge text buffer;
- §9.4: saving `edgeDevices`;
- §12.3: memory checks.

**Decisions:** asked of Codex, `stm32/docs/review/codex-gpt-6-astra-plan09c-design-2026-10-16.md` (D1–D7, all agreed, with details taken in below).

## Global Constraints

- **Keep it simple** (the user): no new mechanism beyond what each item needs. Run only the affected tests; TDD. Codex reviews before the PR.
- **Limits unchanged:**
  - a small config's body is at most 10 240 bytes;
  - `edgeDevices` is at most 49 152 bytes;
  - a certificate is at most 12 288 bytes.
- **Saving `edgeDevices`** checks the syntax (RFC 8259, UTF-8, surrogate pairs, depth ≤ 32) and the root type (an array). Every record is written, then the manifest (spec §9.4).
- **One heap** (`heap_5`, one region), with cJSON's allocations counted. The node limit stays at 100 in 09c.

## Review Focus

1. **A forgotten `free` that the arena used to hide.** Every API handler's cJSON trees and printed strings must be freed, on success and on error. Pinned in T1 by a bench loop of every endpoint, with the heap back to its level.
2. **An `edgeDevices` upload that never ends** (the client goes away, a timeout, a body short of its `Content-Length`). The generation is abandoned and its records deleted; the committed model and the GETs pinned to it stay. Pinned in T3 by `test_store` (abort at every chunk) and the bench (a client that closes mid-body).
3. **A body cut at any byte.** The streaming scanner gives the same verdict as `js_parse_root`, whatever the chunks. Pinned in T2.
4. **Pointers into the freed boot buffer.** Pinned in T4: the host load frees the buffer and then uses the model under ASan.
5. **Heap fragmentation.** A 48 KB boot buffer, a 12 KB certificate buffer, TLS sessions. The largest free block is recorded in T5.

## Rulings to approve

1. **The arena goes** (D1).
   - `web.c` opens no arena scope; `arena_begin`/`arena_end`, `s_web_arena` and `third_party/tlsf` leave the build.
   - `components/arena` keeps only the counting allocator (`json_alloc_install`, `json_alloc_failures`).
   - `/api/status` drops `arenaPeak`, and so do the UI and the bench.
   - `test_arena` goes with TLSF. `test_text_small` and `test_edge_text`, which call `arena_init/begin/end`, move to the counting heap allocator: their content and out-of-memory checks stay, and only the assertions about the TLSF pool go (Codex r1).
2. **`edgeDevices` streams** (D2).
   - The store gains `store_edge_begin(len)`, `store_edge_write(data, n)`, `store_edge_commit(err, errlen)` and `store_edge_abort()`.
   - There is one session at a time. The store's lock is taken in each call, never held between network reads.
   - The new generation is above every record in flash, as today.
   - A second POST while a session is open gets 503, as today.
   - `store_edge_save(text, len)` stays, as begin + write + commit: the existing tests keep covering the write path.
   - The FAL lock and the unknown-commit rules are unchanged.
   - The web feeds `c->recv` to `store_edge_write` at each `MG_EV_READ`.
   - **Only the request whose `store_edge_begin` succeeded owns the session** (a flag on its web slot, Codex r1). Only that request writes, commits or aborts; its close, timeout or error calls `store_edge_abort`. A second POST gets 503 and owns nothing, so its close aborts nothing, and the cleanup after a commit never touches a later session.
3. **The streaming scanner** (`js_stream_t` in `proto/jsonscan`):
   - `js_stream_init(&s, JS_ARRAY)`, `js_stream_feed(&s, data, n)` (false once it is invalid), `js_stream_end(&s)` (true only for one whole value of the root type);
   - an explicit stack of at most 32 levels, and the string, escape, UTF-8 and number states;
   - the same domain as `js_parse_root`.
4. **The boot buffer** (D3).
   - `edge_rt` mallocs 49 152 + 1 bytes and reads the model into it with `store_edge_text`.
   - It frees the buffer after `cfg_edge_load` and before the Edge tasks start, on every early exit too.
   - `web_edge_buffer_for_boot` goes.
5. **Certificates** (D4): a heap buffer of 12 288 + 1 bytes, taken after the headers pass (auth, scope, kind, length) and freed at the end of the request, on every path. For a key, `mbedtls_platform_zeroize` runs before the `free`.
6. **`s_record` (8 KB, static) stays** for GET `edgeDevices` (D5).
7. **The heap grows from 256 KB to 352 KB** (D6). The rest of the freed AXI (about 16 KB) stays free. The real numbers come from the linker map.

**Costs, for the node-limit decision** (ARM sizes):
- a point: `edge_pt_t` 216 B on the heap, plus 242 B of report buffer when the template reports it;
- a device: `edge_dev_t` 104 B; a Modbus TCP device also takes a 5 KB task stack and a connection;
- a bus with devices: a 6 KB task stack;
- the report buffer: 242 B per template slot plus the template's text, at most 26 KB;
- the body: `edgeDevices` stays at most 48 KB. A fully specified point takes about 380 B of JSON, so the body, not the RAM, bounds the model at about 125 such points; the UI's minified bodies with fewer fields allow more.

With 139 KB at the lowest under the heaviest load measured, 100 more points would cost about 22 KB of model and up to 24 KB of report buffer. The node limit stays at 100 in 09c; the user decides.

**Bench findings:**
- `web_check`'s pinned-generations case assumed normalised bodies (since Plan 09b, they are stored as sent): a 9 KB body streams out whole into the send buffers and frees its pin, and a 40 KB one takes 5 sectors per pinned generation, so the fourth save found no room (500). It now saves 17 KB bodies, 3 records: the slow GETs stay pinned and 5 generations fit.
- `test:pages` failed on the System page because a bench run before Plan 09b's fix had left a partial `system` (`{"hostname":…}`); the UI shows the missing fields empty, as the stored bytes are. A factory reset put the defaults back; the device ran with the partial config throughout.
